# 전길원 포트폴리오

밝은 페이퍼, 코발트 블루 색상의 LLM & Data Engineering 포트폴리오입니다. 프로필 사진을 배치한 첫 화면과 비대칭 프로젝트 배치를 사용합니다.

- GitHub Pages: https://kingrange.github.io/portfolio/
- 이전 비공개 프리뷰: https://kilwon-engineering-notes.kilwon-jeon00.chatgpt.site
- 소스: `sites/kilwon-portfolio/` — Next.js App Router, React, CSS
- 실행: 해당 폴더에서 `npm ci` 후 `npm run dev`
- 검사: `npm test` → `npm run build` → `npm run check:export`
- 프로젝트 본문, 목차: `content/projects.mjs`
- 페이지: `/projects/`에 전체 프로젝트, 메인에는 기존 대표 4개와 개인 백엔드 프로젝트 DCBA를 포함한 5개
- 배포 산출물: `out/` (Next.js 정적 내보내기)

프로젝트 분야 필터와 반응형 레이아웃, 호버, 포커스 인터랙션을 포함합니다. 프로젝트마다 설계, 문제 해결을 문제의 맥락, 설계 판단, 구체적 구현, 결과가 이어지는 사례로 정리합니다. 상세 페이지의 태그는 관련 사례와 목차를 함께 좁히고, 전체 목록에서 기술을 고르면 해당 사례로 바로 연결합니다. 기존 상세 링크는 유지합니다.

## 로컬 문구 편집

```sh
cd sites/kilwon-portfolio
npm run edit
```

터미널에 표시되는 `http://127.0.0.1:4310/__editor/`를 브라우저에서 엽니다. 상단에서 페이지를 선택하고, 미리보기의 문구를 클릭하거나 오른쪽 문구 목록에서 선택해 수정합니다. **미리보기**는 화면에만 적용하고 **저장**은 해당 소스 파일에 반영합니다. 링크를 따라갈 때는 Alt(⌥)를 누른 채 클릭합니다. 종료는 터미널에서 Ctrl+C입니다.

메인 소개와 공통 문구, 프로젝트 제목, 설명, 사례 본문을 편집할 수 있습니다. 링크 주소, 프로젝트 ID, 출처 기록, 필터용 기술 태그는 보호합니다. 같은 파일, 프로젝트 안의 동일 문구는 함께 수정합니다. 다른 편집기에서 파일이 바뀌면 저장을 거부하므로, 입력 내용을 복사하고 새로고침한 뒤 다시 선택합니다.

상단 **프로젝트 추가**에서 분류, 이름, 주소, 담당 업무, 직무, 기술과 첫 사례를 입력하면 전체 목록과 상세 페이지에 추가됩니다. 새 프로젝트는 메인의 대표 프로젝트에는 자동으로 포함되지 않습니다. 코드 주소를 비워두면 비공개로 표시합니다. 첫 사례의 한 줄 요약은 목록의 핵심 설계 설명에도 사용합니다.

**사례 추가**에서는 대상 프로젝트를 선택하고 제목, 주소, 문제 상황, 과제, 작업 내용, 결과, 기술 키워드를 입력합니다. 현재 상세 페이지의 프로젝트가 기본 선택되며, 새 사례는 기존 사례 뒤에 붙습니다. 작업 내용과 처리 흐름은 한 줄에 한 항목, 기술 키워드는 쉼표로 구분합니다. 사례 주소는 해당 프로젝트의 기존 사례, 별칭, 페이지 내부 링크와 겹칠 수 없습니다. 추가 후에는 해당 사례로 이동해 기존 클릭 편집을 계속 사용할 수 있습니다.

추가 입력창을 연 뒤 파일이 외부에서 바뀌면 덮어쓰지 않고 입력을 유지한 채 오류를 표시합니다. 내용을 별도로 복사해두고 입력창을 닫은 다음 새로고침하여 다시 추가합니다. 로컬 편집 서버 코드를 변경한 후에는 실행 중인 `npm run edit`를 종료하고 다시 실행합니다.

편집 서버는 `127.0.0.1:4310`, 미리보기용 Next.js는 `127.0.0.1:4311`에서 실행합니다. 두 포트가 비어 있어야 합니다. 미리보기는 저장 후 다시 불러오며, 다른 편집기에서 변경한 내용은 **새로고침**으로 가져옵니다. 로컬 편집 서버와 편집 화면은 정적 내보내기에 포함되지 않습니다. Next.js에 포함된 Babel 파서를 사용해 편집 가능한 문자열만 찾아 바꾸며, Next.js 업그레이드 시 이 내부 경로가 변경될 수 있습니다.

저장은 로컬 파일에만 반영됩니다. 공개 사이트 배포에는 아래의 커밋, push 과정이 필요합니다.

## 자동 배포

`.github/workflows/pages.yml`은 `main` push 시 검사 → 정적 빌드 → GitHub Pages 배포를 실행합니다. PR에서는 검사와 빌드만 실행합니다. 실패하면 새 버전을 배포하지 않습니다.

최초 한 번 저장소 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 선택합니다. 이후에는 아래처럼 수정한 파일을 커밋하고 push하면 됩니다.

```sh
git add <수정한 파일>
git commit -m "Update portfolio"
git push origin main
```

Actions의 **Deploy portfolio to GitHub Pages** 실행 결과에서 배포 상태를 확인할 수 있습니다. 로컬 파일 저장이나 Notion 수정만으로는 배포되지 않습니다.

Pages는 `/portfolio` 경로로 빌드합니다. 같은 조건의 로컬 검사는 사이트 폴더에서 실행합니다.

```sh
NEXT_PUBLIC_BASE_PATH=/portfolio npm run build
NEXT_PUBLIC_BASE_PATH=/portfolio npm run check:export
```

저장소 이름이나 커스텀 도메인을 바꾸면 워크플로의 `NEXT_PUBLIC_BASE_PATH`도 함께 변경합니다. 로컬 개발에서는 이 환경변수 없이 루트 경로를 사용합니다.
